### 4.2. CFG участка до / после (мысленный — бинарно ничего не менялось)

До:
- `JZ@0x2FC3F9` → (taken) `0x2FC413`: `J→0x2FC432` — **продолжение отрисовки** (далее `LOCAL_U8_LOAD`, `BEGIN_SCALEFORM_MOVIE_METHOD` @`0x2FC438`, `ADD_PARAM_INT` @`0x2FC43e`, `CALL 0x316d2b`, `SWITCH`);
- (fall-through) `0x2FC3FC…0x2FC410` — **error-блок**: LOAD 78678, LOAD 78680, `ILT_JZ→0x2FC410`, STRING+`CALL 0x315922`, **`LEAVE@0x2FC410`** (`2e 02 00`) — функция завершается **без отрисовки**.

После замены `56→55` (JZ→J, тот же размер 3 Б):
- остаётся одно ребро `0x2FC3F9 → 0x2FC413`; **fall-through удаляется**;
- error-блок `0x2FC3FC…0x2FC410` **не имеет внешних целей** (внутренняя цель `ILT_JZ@0x2FC404→0x2FC410` — внутри блока) → становится недостижимым (dead code);
- соседние инструкции и все прочие ветви не затрагиваются (подтверждено обходом: других переходов в регион нет; длина подстановки равна 3 → сдвигов нет);
- **но**: `JZ` снимает условие со стека, `J` — нет → на пути continue остаётся лишнее значение (`depth=1 != 0` на `0x2FC432`, конфликт CFG); подробный разбор и рекомендуемый стеково-сбалансированный **Вариант C1** (`0x2FC3D8` + `0x2FC3F5`) см. в [`e2b-vm-stack-analysis.md`](e2b-vm-stack-analysis.md) и §8.

## 5. Подтверждённые условия блокировки (режим BAWSAQ, `77568≠0`)

Цепочка ворот (short-circuit DUP/INOT/JZ, байтовая логика §4) вычисляет:

```
blocked = !NETWORK_IS_SIGNED_ONLINE ‖ Global_80362 ‖ Global_65064 ‖ Global_65065
```

- `blocked == true` → error-блок: при `78678 < 78680` показывается строка ошибки, затем `LEAVE` — **страница не отрисовывается** (`0x2FC432` недостижим).
- `blocked == false` → `0x2FC413: J→0x2FC432` — отрисовка (scaleform).

Источники блокеров (по коду):

1. **`SIGNED_ONLINE == false`** — офлайн SP без ROS: натив всегда false. Достаточное условие: цепочка истинна **всегда**, независимо от остальных членов.
2. **`Global_65065 == true`** — независимый второй блокер: сидится `standard_global_init` (L185-186), повторно ставится app `f9764` **каждые 120 с** и stock `f4`; очищается **только успешной синхронизацией** → офлайн всегда true.
3. **`Global_65064 == true`** — транзиентный флаг инициализации stock (L85 true / L114 false).
4. **`Global_80362`** — **0 записей во всех 4 YSC** (app1: 125 чтений, stock1: 1 чтение в `f58` = ветка `IS_VEHICLE_STOLEN`, к BAWSAQ отношения не имеет). Источник записи — **вне исследуемых скриптов**. **Не утверждать, что этим флагом можно пренебречь** — setter не найден.
5. `Global_65068` — отдельный ранний выход (§4.3), ставится «полным» портфелем (`full→65068=true` в buy/sell-цепочке).
6. `78678/78680` — не блокируют сами по себе: определяют, показывается ли строка ошибки перед `LEAVE`. Семантика самих глобалов не расшифрована.

**Важно:** обход `iParam1==15` (`INE_JZ@0x2FC3A4`) и LCN-ветка (`0x2FC416`) — штатные альтернативные пути, не связанные с точкой патча.

| 2 | Список бумаг | `f9494`, `f9475` | данные: фильтр `f_9>0 && f_8==Global_77568`; `f_9` заполняется только пост-синхронизацией (stock `func_5`: `STAT_GET_FLOAT→f_9`, `GET_HISTORY 0..4→f_31..f_34`) | Скрыт без синхронизации |

Прочее:

- **Терминация:** `_SHOULD_NETWORK_SCRIPT_TERMINATE` встречается только в `f9755` под `if(Global_80362)` → офлайн SP скрипт **не само-терминируется**.

## 8. Статус гипотезы JZ→J, семантика VM и решение этапа E2b

### 8.1. Подтверждённая семантика `CALL` / `ENTER` / `LEAVE` / `JZ` / `J`

В рамках этапа E2b (см. полную документацию в [`e2b-vm-stack-analysis.md`](e2b-vm-stack-analysis.md)) механика `rage::scrThread::Run` подтверждена по четырём независимым реализациям/спецификациям VM (включая GEN9/Enhanced): `alexguirre/rage-sc-tools`, `calamity-inc/Stand-OSS`, `ShinyWasabi/scrDbg` и `Vali0004/Ovr`:

- `ENTER(p, v, nlen)`: сохраняет `callerFP`, ставит `fp = sp - p - 1`, обнуляет `v` слотов кадра, оставляет стек тела на относительной глубине `0`.
- `LEAVE(p, r)`: сбрасывает `sp = fp + p - 1`, читает `callerFP = fp[p+1]` и `returnAddr = fp[p]` **от `fp`, а не от текущего `sp`**, затем снимает `p` аргументов и при `r > 0` копирует `r` возвращаемых значений с `old_sp - r + 1`.
- `JZ` (`0x56`): `--sp; if (sp[1].Int == 0) JUMP(...)` (`-1` слово). `J` (`0x55`): `0` слов.

### 8.2. Вывод по гипотезе `JZ -> J` (`0x2FC3F9`) и выбор Варианта C1

- Хотя `LEAVE(2, 0)` в `func_9474` не читает `returnAddr` относительно `sp` и отбрасывает лишнее слово на выходе, замена `JZ -> J` (Вариант A) **создаёт конфликт глубины стека (`1 != 0`) на точке слияния `0x2FC432`**, оставляет лишнее слово на стеке на протяжении 838 инструкций и убирает проверки `Global_65064` и `Global_80362` — поэтому **Вариант A отклонён**.
- По итогам полного анализа всех 123 базовых блоков `func_9474` и соседних функций `app1::func_9764` / `stock1::func_4` (переустановка `Global_65065 = 1`) для экспериментального in-memory теста **C1** выбран **Вариант C1** (0-дельта стека, 0 конфликтов CFG, сохранены `G65064` и `G80362`, LCN не затронут, нейтрализована перезапись `G65065 = 1`):
  - `0x2FC3D8` (`2c 01 05 04` `NATIVE NETWORK_IS_SIGNED_ONLINE`) → `72 00 00 00` (`PUSH_CONST_1; NOP; NOP; NOP`),
  - `0x2FC3F5` (`53 29 fe` `GLOBAL_U16_LOAD Global_65065`) → `71 00 00` (`PUSH_CONST_0; NOP; NOP`).

### 8.3. Отказ от модификации `.ysc` на диске

- Файлы `game-scripts/*.ysc` остаются неизменными (`SHA256` §1.1); постоянные бинарные патчи не изготавливаются. Вся детальная таблица 123 блоков и сравнение опций (`A`, `B`, `C1`, `D1`) вынесены в [`e2b-vm-stack-analysis.md`](e2b-vm-stack-analysis.md).

## 9. Ограничения и нерешённые вопросы

1. Статический аудит VM, CFG `func_9474` и безопасный вариант **C1** завершены в [`e2b-vm-stack-analysis.md`](e2b-vm-stack-analysis.md); фактическое поведение пустого UI BAWSAQ при открытых воротах в памяти процесса ещё не проверялось (ожидает C1).
2. Setter `Global_80362` не найден (0 записей в 4 YSC; в E1 в SP стабильно `0`) — Вариант C1 сохраняет проверку `Global_80362` без изменений.
3. `*2.ysc` полностью декодируются через `v1` (128 опкодов) в `tools/ysc_disasm.py` (см. [`e2a-format-analysis.md`](e2a-format-analysis.md)) и являются неактивным base-слоем `x64b.rpf`.
4. Бинарные паттерны/структура сборки `2.0.1158.16` (`.exe`) и поведение `STAT_COMMUNITY_*` офлайн в процессе не модифицировались.
5. `78678/78680` расшифрованы: `func_9474 @ 0x2FC3FC..0x2FC404` проверяет `Global_78678 < Global_78680` (`ILT_JZ`), а `func_9733 @ 0x315922` ставит кулдаун показа баннера `Global_78678 = Global_78680 + 1000`.
6. Стартер `stock_controller` не идентифицирован (в рантайме E1 подтверждена одновременная работа с `appinternet`).

- **E1 (выполнен на живой игре `2.0.1158.16`):** подтвердил `SIGNED_ONLINE=false`, `ROS=false`, `G80362=0`, `G65064=1->0`, `G65065=1`, `G77568=0->1` при открытии вкладки BAWSAQ и ошибку `WWW_BAWSAQ_COM_S_ERROR` (`docs/bawsaq-restoration/experiment-e1.md`).

  1. Проверить заголовок `scrDbg` (`GTA5_Enhanced.exe 1158.16-1.73`), поток `appInternet` (`0x6A172273`, `Code Size = 3242324`) и 36-байтовую сигнатуру на `0x2FC3D8` (`Alt+B`).
