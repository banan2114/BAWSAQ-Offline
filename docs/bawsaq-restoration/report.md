### 4.2. CFG участка до / после (мысленный — бинарно ничего не менялось)

До:
- `JZ@0x2FC3F9` → (taken) `0x2FC413`: `J→0x2FC432` — **продолжение отрисовки** (далее `LOCAL_U8_LOAD`, `BEGIN_SCALEFORM_MOVIE_METHOD` @`0x2FC438`, `ADD_PARAM_INT` @`0x2FC43e`, `CALL 0x316d2b`, `SWITCH`);
- (fall-through) `0x2FC3FC…0x2FC410` — **error-блок**: LOAD 78678, LOAD 78680, `ILT_JZ→0x2FC410`, STRING+`CALL 0x315922`, **`LEAVE@0x2FC410`** (`2e 02 00`) — функция завершается **без отрисовки**.

После замены `56→55` (JZ→J, тот же размер 3 Б):
- остаётся одно ребро `0x2FC3F9 → 0x2FC413`; **fall-through удаляется**;
- error-блок `0x2FC3FC…0x2FC410` **не имеет внешних целей** (внутренняя цель `ILT_JZ@0x2FC404→0x2FC410` — внутри блока) → становится недостижимым (dead code);
- соседние инструкции и все прочие ветви не затрагиваются (подтверждено обходом: других переходов в регион нет; длина подстановки равна 3 → сдвигов нет);
- **но**: `JZ` снимает условие со стека, `J` — нет → на пути continue потенциально остаётся лишнее значение (см. §8 — судьба неизвестна, **безопасность не доказана**).

## 5. Подтверждённые условия блокировки (режим BAWSAQ, `77568≠0`)

Цепочка ворот (short-circuit DUP/INOT/JZ, байтовая логика §4) вычисляет:

```
blocked = !NETWORK_IS_SIGNED_ONLINE ‖ Global_80362 ‖ Global_65064 ‖ Global_65065
```

- `blocked == true` → error-блок: при `78678 < 78680` показывается строка ошибки, затем `LEAVE` — **страница не отрисовывается** (`0x2FC432` недостижим).
- `blocked == false` → `0x2FC413: J→0x2FC432` — отрисовка (scaleform).

Источники блокеров (по коду):

1. **`SIGNED_ONLINE == false`** — офлайн SP без ROS: натив всегда false. Достаточное условие: цепочка истинна **всегда**, независимо от остальных членов.
2. **`Global_65065 == true`** — независимый второй блокер: сидится `standard_global_init` (L185-186), повторно ставится app `f9764` **каждые 120 с** и stock `f4`; очищается **только успешной синхронизацией** → офлайн всегда true.
3. **`Global_65064 == true`** — транзиентный флаг инициализации stock (L85 true / L114 false).
4. **`Global_80362`** — **0 записей во всех 4 YSC** (app1: 125 чтений, stock1: 1 чтение в `f58` = ветка `IS_VEHICLE_STOLEN`, к BAWSAQ отношения не имеет). Источник записи — **вне исследуемых скриптов**. **Не утверждать, что этим флагом можно пренебречь** — setter не найден.
5. `Global_65068` — отдельный ранний выход (§4.3), ставится «полным» портфелем (`full→65068=true` в buy/sell-цепочке).
6. `78678/78680` — не блокируют сами по себе: определяют, показывается ли строка ошибки перед `LEAVE`. Семантика самих глобалов не расшифрована.

**Важно:** обход `iParam1==15` (`INE_JZ@0x2FC3A4`) и LCN-ветка (`0x2FC416`) — штатные альтернативные пути, не связанные с точкой патча.

## 8. Статус гипотезы JZ→J и семантика VM

### 8.1. Найденные источники семантики ENTER/LEAVE/CALL

1. **GTAMods Wiki** (`Script_Container`, `SCO`) — текстовые описания:
   - `ENTER(45)`: byte1 — число аргументов, «снимаемых со стека»; 2 байта — число генерируемых переменных; 5-й байт — пропуск имени.
   - `LEAVE(46)`: byte1 — число снимаемых аргументов; byte2 — «**stack number of the return address**».
   - `CALL`: «puts the return address **on top of the stack**».
2. **Реализация `Parik27/ghidra_ysc`** (Ghidra SLEIGH-спека, `data/languages/ysc.sinc`) — операции `ENTER`, `LEAVE` и `CALL` описаны pcode-семантикой (дословно):
   - `ENTER` (op 45): `FP = SP + (imm8*4); SP = SP - (imm16*4);`
   - `LEAVE` (op 46, rcount>0): `RV = *:4(SP + ((imm8_2-1)*4)); SP = FP; return [0:4];`
   - `LEAVE` (op 46, rcount=0): `SP = FP; return [0:4];`
   - `CALL` (op 93): `call Addr24; push32(RV:4);`

   То есть **в модели Ghidra `LEAVE` восстанавливает `SP` через `FP`** и **отдельно считывает возвращаемое значение** со стека (позиция `byte2-1`; при rcount=0 — без чтения).

3. Прочие: RASM — только парсинг полей («parameter count / return variable count»); nj-decompiler — `byte2` как счётчик возвращаемых значений; maybegreat — `LEAVE` только как пропуск (`advpos(2)`). Никто не моделирует стек исполнения.

### 8.2. Почему это НЕ подтверждённая реализация игрового интерпретатора

- `ghidra_ysc` — **сторонняя модель декомпилятора** (SLEIGH для реверса/анализа в Ghidra), а не код игрового интерпретатора; например, её `LEAVE` вообще не использует byte1 (argcount).
- Источники **расходятся по формулировкам**: GTAMods называет byte2 «stack number of the return address», наблюдаемые байты на всех 14 выборочных функциях: **byte2 == rcount (0 или 1)**; Ghidra читает из этой позиции возвращаемое значение и делает `SP=FP`. Как это соотносится с адресом возврата в **игровой** VM — не установлено.
- Игровой интерпретатор недоступен: `unknowncheats #493135` (сниппеты содержат реальный `case 44u` с `stack_pointer`) — закрыт Cloudflare-проверкой; `Vyzerythe/Leonida` (PR #26 с интерпретатором VM) — **DMCA 451, навсегда недоступен**.

### 8.3. Вывод по стеку (соответствует директиве 2026-09-27)

> **Точная механика возврата и судьба лишних значений на стеке в игровом VM не подтверждены. GTAMods и Ghidra дают полезные сведения, но не закрывают вопрос. Семантика ENTER/LEAVE/CALL — НЕ ПОДТВЕРЖДЕНА.**
>
> **Безопасность JZ→J не доказана:** `JZ` снимает условие со стека, `J` — нет → на пути continue потенциально остаётся лишнее значение; неизвестно, что с ним делает игровой `LEAVE` (отбрасывает ли через `SP=FP`, либо индексирует адрес возврата от вершины стека — при этом лишнее значение сместит позицию).
>
> **Патч не применять. Бинарный патч не готовить** до подтверждения семантики. Все рассмотренные варианты (A JZ→J, B const-condition, C DROP+J, D прочие) — **ON HOLD** в [`interim-vm-stack-analysis.md`](interim-vm-stack-analysis.md).

## 9. Ограничения и нерешённые вопросы

1. Семантика `ENTER/LEAVE/CALL` игрового VM — **не подтверждена** (§8); безопасность JZ→J — не доказана; патч не готовится и не применяется.
2. Setter `Global_80362` не найден (0 записей в 4 YSC) — **не считать флаг пренебрежимым**.
3. Маппинг файл↔RPF (`update2`/`x64b`) — гипотеза, нужен OpenIV.
4. «2»-файлы: истинная нумерация опкодов P не установлена (счётчики устойчивы); глобальная нумерация другая (80362 raw = 0).
5. Бинарные паттерны/структура сборки 1158.16 (exe) не исследовались.
6. Поведение `STAT_COMMUNITY_*` офлайн не проверено (ожидание: история пуста — не доказано в игре).
7. Заголовочный `globals_count` парсится в 0 — не использовать.
8. Семантика `78678/78680` (условие показа строки ошибки) не расшифрована.
9. Стартер `stock_controller` не идентифицирован; зависимость appinternet от `appemail/context_controller/laptop_trigger` — по контексту запуска.
10. Фактические значения гейта в игре (§5 п.3) не наблюдались — см. E1.

## 10. Рекомендуемый следующий эксперимент (проверка гипотезы в игре)

Цель: проверить гипотезу «страница BAWSAQ не отрисовывается из-за OR-цепочки ворот `0x2FC3F9`, при этом торговля/портфель/локальные функции не зависят от сети» — **без изменения игровых файлов**.

### E1 — базовый (немедленный, read-only, без каких-либо изменений)

1. Запуск **GTA V Enhanced без ROS** (офлайн SP). Перед запуском зафиксировать SHA256 четырёх YSC (§1.1) — после прогона сверить, что не изменились.
2. Телефон → открыть BAWSAQ; записать **точную стадию отказа**: (а) страница открылась/не открылась; (б) какой текст/иконка ошибки; (в) виден ли список бумаг; (г) котировки/графики (ожидание: пусто — **не называть их работающими**).
3. Read-only проба (SHVDN/ASI, ничего не пишет в файлы) в момент открытия зафиксировать: `NETWORK_IS_SIGNED_ONLINE` (`0x261e3728ee56b3ac`), `Global_65064/65065/80362/77568/65068/78678/78680`, сработал ли `BEGIN_SCALEFORM_MOVIE_METHOD` (idx 103) для BAWSAQ-мови.
4. Проверить локальную часть: LCN-список, покупку/продажу, портфель — работают ли офлайн (разделение §6).
5. Зафиксировать результат по стадиям; при провале — **записать точную стадию и диагностику, не маскировать дополнительными патчами**.

Ожидание по гипотезе: `SIGNED_ONLINE=false` и `65065=true` → цепочка истинна → ворота не пройдены → `LEAVE@0x2FC410` без `BEGIN_SCALEFORM` → страница не отрисована; торговля/портфель при этом работают.

### E2 — причинный (in-memory, только после решения по семантике VM; файлы НЕ изменяются)

Если E1 подтвердил условия: в **живом процессе** (паттерн-скан памяти по последовательности §4.1, контекст `53 29 fe 20 56 17 00 62 56 33 01`) переключить один байт `56→55` **в копии памяти**, повторить сценарий E1, записать: открылась ли страница, поведение списка/котировок/графиков, отсутствие побочных эффектов LCN и крашей. Откат = **перезапуск игры** (файлы на диске не менялись; SHA256 сверить).

Риски E2: неизвестна судьба лишнего значения на стеке (§8.3) → возможна ошибка скрипта/краш; наблюдение фиксируется как **экспериментальный обход, а не доказанно безопасный патч**. Постоянный бинарный патч файла остаётся **запрещённым** до подтверждения семантики VM; подмена UI и отключение непроверенных проверок запрещены.
