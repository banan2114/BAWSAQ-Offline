# Эксперимент E1 — протокол и таблица результатов

Проверяемая гипотеза (из [`report.md`](report.md) §5, §6, §10): **офлайн страница BAWSAQ не отрисовывается из-за OR-цепочки ворот `func_9474` (`0x2FC3F9`: `!SIGNED_ONLINE ‖ 80362 ‖ 65064 ‖ 65065`), при этом локальная функциональность (LCN-список, покупка/продажа, портфель) от сети не зависит.**

Инструмент: [`tools/bawsaq-diagnostics/`](../../tools/bawsaq-diagnostics/) → `BawsaqE1Diagnostics.dll` (read-only, см. [`diagnostic-tool.md`](diagnostic-tool.md)).

## 0. Правила безопасности (обязательны)

- Плагин **только читает** состояние; никаких записей в глобалы/статистику/память, никаких хуков, никаких изменений YSC и архивов.
- **YSC не изменяются.** Перед и после прогона сверить SHA256 четырёх файлов (команды ниже) — отклонение = провал эксперимента, немедленная остановка.
- Никаких дополнительных патчей «для чистоты теста». При провале — фиксация стадии и диагностика, **без маскировки**.
- Не запускать GTA Online. Сценарий B — только одиночный режим с ROS-авторизацией.

```powershell
# PowerShell из папки game-scripts (или с полными путями):
Get-FileHash .\appinternet1.ysc, .\appinternet2.ysc, .\stock_controller1.ysc, .\stock_controller2.ysc -Algorithm SHA256
```
Ожидаемые значения — [`report.md`](report.md) §1.1.

## 1. Подготовка

1. Убедиться, что загружена SHVDNE **v1.1.0.6** (строка `ScriptHookV .Net Enhanced 3.9.0.6 (1.1.0.6)` в логе SHVDN).
2. Скопировать `BawsaqE1Diagnostics.dll` (из `tools/bawsaq-diagnostics/dist/`) в `<GTA V>\scripts\`.
3. Записать SHA256 DLL из `dist/SHA256SUMS.txt` (для протокола).
4. Запустить игру **без ROS** (см. сценарий A), дождаться главного меню/SP.
5. Проверить, что в `<GTA V>\scripts\bawsaq-e1-diagnostics.log` появился заголовок (см. [`diagnostic-tool.md`](diagnostic-tool.md) §7) и строка `INITIAL ...`. Если её нет — раздел «Диагностика провалов», шаг D1.

## 2. Сценарий A — Offline (без ROS)

| Шаг | Действие | Фиксация |
|---|---|---|
| A1 | Запуск игры без подключения к ROS, вход в SP | появился ли `INITIAL` в логе |
| A2 | **F9** — базовый снимок в главном меню/после загрузки SP | `MANUAL`-строка №1 |
| A3 | Открыть телефон → приложение BAWSAQ | **визуально:** открывается ли страница; если нет — какой текст/иконка; искать ошибку **`WWW_BAWSAQ_COM_S_ERROR`** (зафиксировать дословно: да/нет/иной текст) |
| A4 | В момент открытия/ошибки — **F9** | `MANUAL`-строка №2 (это основной снимок гипотезы) |
| A5 | Осмотреть список бумаг, котировки, графики | виден ли список; котировки/графики: заполнены/пусты (**пустые ≠ «работающие»**) |
| A6 | **F9** ещё раз после закрытия BAWSAQ | `MANUAL`-строка №3 |
| A7 | Проверить LCN-список (LCN-режим телефона) | работает ли локально, без изменений |
| A8 | Проверить покупку/продажу и портфель (одна операция, локальная) | работает ли; **портфель/сейв не менять лишним** — одна проверочная операция, при сомнениях пропустить и отметить «не проверено» |
| A9 | Выход из игры | есть ли `SESSION_ABORTED`; сверить SHA256 YSC снова (должны совпасть) |

**Ожидания по гипотезе (report §5) — заполнить по факту:**
- `signed_online=False` (натив `NETWORK_IS_SIGNED_ONLINE`);
- `ros=False` (`NETWORK_HAS_VALID_ROS_CREDENTIALS`);
- `G65065=1` (сидится при инициализации, очищается только успешной синхронизацией);
- `G65064` — 0/1 (транзиентный, может переключаться);
- `G77568` — 0 в меню; ≠0 при открытии режима BAWSAQ (страница `appinternet`);
- `G80362` — **заранее неизвестно** (0 записей в 4 YSC → источник вне исследуемых скриптов) — фиксируется как есть;
- `G77542` — `-1` появляется на раннем error-пути (`G65068≠0`); обычно 0.

**Нюанс, важный для интерпретации:** строка ошибки в error-блоке ворот показывается только при условии `78678 < 78680` (report §4.3, §5) — **страница может не отрисоваться и без видимой ошибки**. Отсутствие `WWW_BAWSAQ_COM_S_ERROR` при `signed_online=False` **не опровергает** гипотезу; зафиксировать и это состояние.

## 3. Сценарий B — Online-эталон (опционально, только SP с ROS)

Выполняется **только если** доступна безопасная авторизация ROS в одиночном режиме (Social Club/лаунчер). **GTA Online не запускать и не требуется.**

1. Запуск с ROS → вход в SP → **F9** (B1).
2. Повторить шаги A3–A6 (открыть BAWSAQ, **F9** в момент открытия) → B2.
3. Зафиксировать, отличаются ли `signed_online`/`ros` и глобалы от сценария A.
4. SHA256 YSC после — совпадают.

**Ожидания:** `signed_online=True` и/или `ros=True` при живой ROS; если страница при этом открывается — прямое подтверждение, что блокировка привязана к сетевым условиям ворот. Значения `G65065` и др. сравниваются с A по таблице ниже (при успехе синхронизации `65065` может сбрасываться — это тоже данные).

## 5. Диагностика провалов (по стадиям, без маскировки)

| Стадия | Симптом | Что записать |
|---|---|---|
| D1 | Нет строки заголовка/`INITIAL` в логе | лог SHVDN (ошибки загрузки скрипта), наличие DLL в `scripts\`, версию SHVDNE; проверить, что DLL собрана против **v1.1.0.6** |
| D2 | Есть заголовок, но `signed_online=ERR:...`/`G...=ERR:IndexOutOfRange` | дословный текст `ERR`, `game_file_version`/`raw` из заголовка; **не** менять индексы и не пересобирать «подправив» — это результат |
| D3 | Лог не создаётся вообще | путь из заголовка недостижим → `%TEMP%\bawsaq-e1-diagnostics.log`; права на запись папки `scripts` |
| D4 | BAWSAQ: страница не открылась, ошибки нет | зафиксировать: `signed_online`/`ros`/`G77568` снимка A4; напомнить нюанс `78678<78680` (§2) |
| D5 | BAWSAQ: страница открылась offline (против гипотезы!) | зафиксировать все значения A4 + дословно текст на экране; **не** объяснять «наверное, повезло» — это опровержение, записать как таковое |
| D6 | SHA256 YSC изменились | **стоп.** Записать расхождение; ни один шаг протокола не пишет в YSC — причину расследовать до продолжения |

При любом провале: точная стадия (A2–A9 / D1–D6) + содержимое лога и лога SHVDN. Никаких дополнительных патчей или «чтобы заработало» изменений.

## 6. Связь с выводами отчёта

Данные E1 заполняют п.3 таблицы статуса `report.md` («фактические значения в игре не наблюдались») и служат основанием для решения о судьбе гипотезы JZ→J. **Решение о любом патче НЕ принимается на этом этапе:** безопасность JZ→J не доказана (семантика VM — `report.md` §8), а E1 — только диагностика условий блокировки.
