# E2 — Статический аудит источников данных и конвейера BAWSAQ (`2.0.1158.16`)

Настоящий документ фиксирует результаты статического аудита байткода скриптов сборки **GTA V Enhanced `2.0.1158.16`** (Этап E2) в части потоков данных LCN/BAWSAQ, структур глобальной памяти, зависимостей от сетевых/ROS-нативов, механизма синхронизации `STAT_COMMUNITY_*`, UI-отрисовки и торгового контура.

**Область исследования и ограничения инструментов:**
- Полностью дизассемблированы и проанализированы «1»-скрипты (Legacy/Gen8+Enhanced):
  - `game-scripts/stock_controller1.ysc` — **109 функций** (`func_0..func_108`), таблица нативов `75` записей (`tools/xmap_stock1.json`).
  - `game-scripts/appinternet1.ysc` — **9801 функция**, таблица нативов `1315` записей (`tools/xmap_app1.json`).
- **Ограничение по «2»-скриптам (`appinternet2.ysc`, `stock_controller2.ysc`):** штатный `tools/ysc_disasm.py` завершается ошибкой на обоих файлах:
  - `game-scripts/appinternet2.ysc` (`natives_count = 440`, `code_size = 351139`): `ValueError: native index 512 out of range at 0x477`.
  - `game-scripts/stock_controller2.ysc` (`natives_count = 70`, `code_size = 37725`): `ValueError: unknown opcode 208 at 0x4d2`.
  - Причина: таблица опкодов в `tools/ysc_disasm.py` соответствует формату «1»-скриптов, но не перестановке опкодов/формату операндов «2»-файлов. Поэтому все конкретные адреса и смещения в данном документе относятся к `stock_controller1.ysc` и `appinternet1.ysc`; структура данных и логика «2»-файлов статически **не декодированы**.

> Примечание к `report.md`: в раннем отчёте (`report.md`, §1.1/§8.3) номера функций `f53/f54/f58/f106/f110` были отнесены к `stock_controller1`, хотя в `game-scripts/stock_controller1.ysc` всего 109 функций (`func_0..func_108`); указанные номера `func_53/54/55/57/58/106/110` принадлежат `appinternet1.ysc`. В данном документе для каждой функции явно указывается скрипт-источник.

### 1.2. Таблица хэшей статов BAWSAQ `Global_60260[0..38]` (`stride = 7`)

Заполняется в конце `stock_controller1::func_107` (`0x8d5e..0x96ce`) для `39` BAWSAQ-акций (`f_35 = 0..38`):
- `Global_60260[k].f_0` (`+0`) — хэш **общего (community) float-стата** цены на сервере ROS (используется в `STAT_GET_FLOAT` и `STAT_COMMUNITY_GET_HISTORY`).

Статы `.f_3[0..2]` служат лишь для зеркалирования/телеметрии.

### 1.4. Сейв-структура `Global_114990.f_20573` — почему LCN-хранилище не вмещает BAWSAQ

Проверка смещений в `stock_controller1::func_94, 91, 84, 85, 27` и `appinternet1::func_55, 57, 104..106, 110, 9493` выявляет жёсткий размер массивов внутри сохраняемого блока `Global_114990.f_20573`:

- `f_101`: флаг «LCN уже инициализирован в сейве» (`0` → `1` в `stock1::func_94`).
- `f_103[42]` (`stride 1`): сохранённые базовые цены `.f_9` **только для LCN** (`0..40`, вместимость `42`).
- `f_146[42]` (`stride 1`): сохранённые максимумы `.f_31` **только для LCN** (`0..40`).
- `f_189[42]` (`stride 1`): сохранённые минимумы `.f_32` **только для LCN** (`0..40`).
- **Портфель SP-персонажей (до 10 позиций на персонажа)** — три параллельных блока по `33` поля внутри `Global_114990.f_20573` (подтверждено по `stock1::func_86` @ `0x4e40..0x4f12`):
  - `char 0` (Michael): ID бумаг `+0` (`[0..9]`), количество акций `+22` (`f_22[0..9]`);
  - `char 1` (Franklin): ID бумаг `+33` (`f_33[0..9]`), количество акций `+55` (`f_55[0..9]`);
  - `char 2` (Trevor): ID бумаг `+66` (`f_66[0..9]`), количество акций `+88` (`f_88[0..9]`);
  - читаются/пишутся также в `app1::func_104, 105, 98, 55, 57, 106, 110` и `func_9493` для **любых** `stockIdx`, включая BAWSAQ!
- `f_442` (`int`), `f_443[8]`, `f_452[8]`, `f_461[8]`: окно сюжетных/динамических модификаторов цен (`stock1::func_27` декрементирует длительность, `stock1::func_7` / `app1::func_100` применяют коэффициенты через `stock1::func_9` / `app1::func_101`).

**Важный архитектурный вывод (разделение сохранения и отображения):**
- **Подтверждённое сохранение портфеля:** сейв-буферы цен `f_103/146/189` имеют размер `42` элемента и физически не способны хранить `80` акций (`41 LCN + 39 BAWSAQ`). Напротив, хранение портфелей (`+0/+22`, `+33/+55`, `+66/+88`) индексируется по общему индексу `Global_57379[0..79]` и уже сохраняет BAWSAQ-позиции в SP-сейв: `stock1::func_85` лишь зеркалирует их в `STAT_SET_INT` (записывая `0` в стат при `f_9 <= 0`), но **сам сейв-портфель не стирает**.
- **Подтверждённое поведение отображения при нулевой цене (`.f_9 == 0.0`):** `app1::func_9493` (`0x2fefe1..0x2ff117`) читает сохранённые слоты портфеля (`func_105` / `func_104` / `func_98`), однако перед отрисовкой строки в Scaleform (`SET_DATA_SLOT`) вызывает `func_103(stockIdx)` (`0x2ff04f`) и проверяет `func_103(stockIdx) > 0.0` (`0x2ff055..0x2ff059`). Поскольку `func_103` (`0x5e0b`) для BAWSAQ (`f_8 != 0`) возвращает `func_99(idx)` (от `.f_9`), **для видимости сохранённой BAWSAQ-позиции в UI портфеля строго требуется `.f_9 > 0.0`** — при `.f_9 == 0.0` позиция остаётся в сейве, но в интерфейсе `My Portfolio` не отображается.

## 2. Конвейер цен и разделение LCN / BAWSAQ (`stock_controller1.ysc`)

### 2.1. Жизненный цикл `stock_controller1::func_0` (`0x0..0x1fe`)

1. **Инициализация (один раз при запуске скрипта):**
   - `Global_65064 = 1` (`0x60`).
   - `func_107()` (`0x76`) → заполняет `Global_57379[0..79]`, `Global_60260[0..38]`, `Global_60534`, `Global_60822`.
   - Цикл `0..203` (`0x7d..0xef`) читает начальные значения телеметрии `Global_60822` через `STAT_GET_INT`/`STAT_GET_FLOAT`.
   - `func_97()` (`0xf2`) → выходит сразу, если `!NETWORK_IS_GAME_IN_PROGRESS()`.
   - `func_95()` (`0xf6`) → инициализирует новости (`Global_64926`).
   - `func_94()` (`0xfa`) → **только `f_8 == 0` (LCN):** если `Global_114990.f_20573.f_101 == 0`, генерирует стартовые `.f_9` (в диапазоне `~15..290`) и 16 точек истории, выставляет `f_101 = 1`.
   - `func_91()` (`0xfe`) → **только `f_8 == 0` (LCN):** восстанавливает `.f_9`, `.f_31`, `.f_32` из `Global_114990.f_20573.f_103/146/189`, синтезирует `.f_14[0..15]` и `.f_33/.f_34`.
   - `Global_65064 = 0` (`0x103`).
   - `func_90(1)`, `func_87()`, `func_84()` (`0x107..0x10f`).
     - **`func_84() -> func_85()` (`0x4dc1..0x4ee6`) — критично для BAWSAQ-портфеля:** проходит по слотам портфеля `f_233[char].f_3[0..9]` и для бумаг с `f_8 == 1` проверяет `f_9 > 0.0`:
       - если `f_9 <= 0.0` (BAWSAQ не загружен), обнуляет стат `STAT_SET_INT(Global_60260[f_35].f_3[char], 0, 1)`, но при `f_9 <= 0` также важно проверить, не чистит ли слот (фактически если акции ещё не загружены, UI портфеля `func_9493` просто скрывает строки, где `func_103(idx) <= 0.0`).
2. **Главный цикл (`0x113..0x1fb`, `WAIT(0)`):**
   - В SP (`!NETWORK_IS_GAME_IN_PROGRESS() && !func_79(14)`):

     - `func_1()` (`0x1f2`) → `func_2()`: отправка исходящей телеметрии `Global_60822` через `STAT_GET_INT`/`STAT_SET_INT` (входящие цены не изменяет).

### 2.2. Эффективная цена и сюжетные множители (`func_6`/`func_7` и `app1::func_99`/`func_100`)

Оба скрипта вычисляют итоговую рыночную цену одинаковой формулой:
- `stock1::func_6(i)`: `FLOOR(Global_57379[i].f_9 * stock1::func_7(i) * 100.0) / 100.0`
- `app1::func_99(i)`: `ROUND(FLOOR(Global_57379[i].f_9 * app1::func_100(i) * 100.0)) / 100.0`

Проверка всех 8 жёстко зашитых в `switch` сюжетных/миссионных индексов `func_7` / `func_100` (`0x10=16, 0x34=52, 0x38=56, 0x3b=59, 0x3d=61, 0x42=66, 0x45=69, 0x49=73`): **все 8 принадлежат LCN (`f_8 == 0`)**. Вместе с тем та же функция `func_7`/`func_100` применяет общий механизм временных бустов `Global_114990.f_20573.f_442` (`f_443[0..7]`) через `func_9`/`func_101`, который работает **для любого индекса `0..79`**, включая BAWSAQ-акции.

## 3. Сетевой цикл BAWSAQ: `STAT_COMMUNITY_*`, таймеры и проверки

Реальный конвейер BAWSAQ состоит из трёх точек: запуск синка в `appinternet1`, приём результатов в `stock_controller1`, и подгрузка 6-точечного графика при открытии карточки бумаги в `appinternet1`.

```
[Открытие браузера / app1::func_0 @ 0x18e]
   └─▶ app1::func_9764 (0x317337..0x317392)
         ├─ проверка кулдауна: (GET_GAME_TIMER() - G62253) > 120000 || G62253 == -1
         ├─ !NETWORK_IS_SIGNED_ONLINE()       ──▶ G65065 = 1; выход
         ├─ !NETWORK_HAS_VALID_ROS_CREDENTIALS() ──▶ G65065 = 1; выход
         └─ !G62252 ──▶ STATS::STAT_COMMUNITY_START_SYNCH()
                        G62253 = GET_GAME_TIMER()
                        G62252 = 1

[Каждый кадр / stock1::func_0 @ 0x1ee]
   └─▶ stock1::func_4 (0x2b1..0x2fb)
         ├─ !NETWORK_IS_SIGNED_ONLINE() && G62252 != 0
         │     ──▶ G62252 = 0; G62253 = GET_GAME_TIMER(); G65065 = 1
         └─ NETWORK_IS_SIGNED_ONLINE() && G62252 != 0 && !STAT_COMMUNITY_SYNCH_IS_PENDING()
               ──▶ failCount = stock1::func_5()
                   G62252 = 0
                   если failCount < 5 ──▶ G65065 = 0

[Внутри stock1::func_5 (0x2fe..0x494)]
   ├─ если !SIGNED_ONLINE || !HAS_VALID_ROS_CREDENTIALS ──▶ return 1
   └─ цикл i = 0..79: если f_8 != 0 && f_35 > -1:
        hash = Global_60260[f_35].f_0
        STAT_GET_FLOAT(hash, &f_9, -1)
        если f_9 > 0.0:
          STAT_COMMUNITY_GET_HISTORY(hash, 0, &f_33)   // f_33 как временный буфер
          f_31 = f_9; f_32 = f_9; sum = hist[0]
          для k = 1..4:
            STAT_COMMUNITY_GET_HISTORY(hash, k, &val)
            обновить f_31=max, f_32=min; sum += val
          avg5 = sum / 5.0
          price = func_6(i)                            // с учётом func_7(i)
          обновить f_31=max(..., price), f_32=min(..., price)
          f_33 = price - avg5
          f_34 = (f_33 / avg5) * 100.0
        иначе: failCount++
```

**Наблюдаемые последствия в офлайн SP (подтверждено в E1 на `2.0.1158.16`):**
1. `NETWORK_IS_SIGNED_ONLINE = false`, `NETWORK_HAS_VALID_ROS_CREDENTIALS = false`.
2. `app1::func_9764` при запуске браузера выставляет `Global_65065 = 1`, не вызывая `STAT_COMMUNITY_START_SYNCH()`.
3. `stock1::func_4/func_5` никогда не заполняет `Global_57379[i].f_9` и `.f_31..f_34` для BAWSAQ (`f_8 == 1`) — они остаются `0.0` (`f_32 = FLT_MAX`), а `Global_65065` остаётся `1`.
4. **Примечание:** если в офлайне открыть только гейт, но оставить `f_9 == 0.0`, все BAWSAQ-бумаги всё равно будут отфильтрованы проверкой `.f_9 > 0.0` в `func_9494` (`0x2ff144`) и `func_9498` (`func_9475` также требует `.f_9 > 0.0`).

### 3.1. Подкачка 6-точечного графика BAWSAQ (`app1::func_9490`, `0x2fecb7..0x2fee47`)

Вызывается со страницы деталей акции `app1::func_9487` (`0x2fe389`, когда `f_8 != 0`), а также как fallback из `func_9491`:
1. **Жёсткая сетевая проверка (`0x2fecbc..0x2feccf`):** если `!NETWORK_IS_SIGNED_ONLINE() || !NETWORK_HAS_VALID_ROS_CREDENTIALS()` → немедленный `LEAVE` (ось X и ось Y графика не передаются в Scaleform).
2. Проверяет `f_8 == 1` (`0x2fecd9`) и `f_35 != -1` (`0x2fece9`).
3. Передаёт в Scaleform подписи оси X: `SET_DATA_SLOT(slot1, "BS_PH_5", ..., "BS_PH_0", 1.5f)` (`0x2fecf2..0x2fed41`).
4. Берёт `p = func_103(stockIdx)`, обновляет `.f_31`/`.f_32` относительно `p`.
5. Определяет `blend = (p != Global_57379[0].f_9)` (особенность оригинального скрипта: на `0x2feda2` реально индексируется `local8 = 0`, а не `stockIdx`), затем читает 5 точек `k = 0..4` через `STAT_COMMUNITY_GET_HISTORY(Global_60260[f_35].f_0, k, &val)`:
   - При `blend == 1` плавно подтягивает исторические точки к `p`: `(1 - 0.2*k)*val + (0.2*k)*p`.
   - Считает `avg6 = (p + sum(hist[0..4])) / 6.0` (**отличие от `stock1::func_5`**, где среднее берётся по 5 точкам!).
   - Перезаписывает `.f_33 = p - avg6` и `.f_34 = ((p - avg6) / avg6) * 100.0`.
   - Добавляет `p` шестой (текущей) точкой и закрывает `END_SCALEFORM_MOVIE_METHOD`.

## 5. Сводная карта неизвестных величин

1. **Байткод «2»-файлов (`appinternet2.ysc`, `stock_controller2.ysc`):** на этапе E2 не декодировался старым `tools/ysc_disasm.py` (`native index 512 out of range` / `unknown opcode 208`). На последующем этапе **E2a** декодирование «2»-файлов полностью решено (таблица `v1` на 128 опкодов) и подтверждено, что в GTA V Enhanced `2.0.1158.16` исполняется пара `*1.ysc` (`update2.rpf`), а `*2.ysc` (`x64b.rpf`) — базовые непатченные скрипты (см. [`e2a-script-resolution.md`](e2a-script-resolution.md) и [`e2a-format-analysis.md`](e2a-format-analysis.md)).
2. **`Global_80362`:** 0 записей в 4 YSC; источник установки остаётся за пределами этих файлов (в E1 в SP стабильно равен `0`).
3. **Начальный сеттер `Global_65065 = 1` и `Global_62253 = -1`:** вероятно находится в скрипте инициализации глобалов (`startup` / `standard_global_init`), не включённом в `game-scripts/`.
4. **Субструктура `Global_114990.f_20573.f_233[0..2 /*69*/]`** (проверяется в `stock1::func_0` @ `0x120..0x14c` для `f_1 < 11`): точный маппинг всех полей за пределами портфельных блоков `+0..+98` и буферов цен `f_103/146/189` полностью не расписывался, так как для восстановления BAWSAQ достаточны `Global_57379` и портфельные хелперы `func_104/105/98`.
5. **Семантика VM при обходе условных переходов (`report.md`, §8.3):** `ysc_disasm.py` не доказывает состояние стека при нештатной подмене опкода `JZ → J`, поэтому в архитектуре E2 предпочтительнее опираться на данные/глобалы либо минимальные безопасные решения с учётом стека (см. `e2-architecture.md`).
