## 2. Подтверждённые факты (получены инструментами tools/, повторяемы)

- `func_9474` @ `0x2FC392`: 882 инструкции; до гейта 43 (44 с гейтом), после — 838. Дамп контекста: `/tmp/gate_dump.txt` (81 строка, 40 инструкций с каждой стороны, маркер ` <== GATE`).
- Инструкция @ `0x2FC3F9`: opcode `0x56` (`JZ`), длина 3 байта, операнд i16 `0x0017`, цель `0x2FC413` (вычисление `0x2FC3F9+3+0x17` совпадает).
- Соседи стык в стык: `IOR` @ `0x2FC3F8` (1 байт, кончается ровно на `0x2FC3F9`), `GLOBAL_U24_LOAD` @ `0x2FC3FC` (начинается ровно после).
- CFG участка (до): `JZ@0x2FC3F9` → ветка ветвится на `0x2FC413` (continue, условие==0) и `0x2FC3FC` (error-блок). Error-блок `[0x2FC3FC..0x2FC410]` не имеет внешних входов, кроме внутреннего `ILT_JZ@0x2FC404 → 0x2FC410`. ЛКН-ветка `@0x2FC416` и `INE_JZ@0x2FC3A4 → 0x2FC432` не зависят от гейта.
- CFG (после замены `JZ→J`, умозрительно): `JZ` теряет ребро fall-through в error-блок; error-блок становится недостижимым (мёртвый код); все соседние инструкции и другие ветки не меняются (заменяется ровно 1 байт, длины инструкций не меняются).
- **Стек (суть проблемы):** `JZ` снимает значение-условие со стека (pop) и прыгает, если оно == 0. `J` — безусловный переход **без pop**. При замене `JZ→J` значение OR-цепочки `(!SIGNED_ONLINE || 80362 || 65064 || 65065)` остаётся на стеке при входе на `0x2FC413` и далее до конца `func_9474`. Оригинальный код обеих веток предполагает, что условие уже снято.

## 5. Семантика ENTER / LEAVE / CALL для GTA V RAGE Script VM — источники

### 5.1 Проверенные источники на момент написания

| Источник | Что даёт | Статус |
|---|---|---|
| GTAMods Wiki, «Script Container» (gtamods.com/wiki/Script_Container) | Текстовые описания: **ENTER** — «byte after the opcode indicates the amount of arguments the function takes off the stack, next 2 bytes — number of variables to generate on the stack»; **LEAVE** — «byte after the opcode indicates the amount of arguments that will have to be popped off the stack, and the next byte after that indicates **the stack number of the return address**»; **CALL** (стр. SCO) — «puts the return address on top of the stack» | **Частично:** текст есть, но база нумерации «stack number» не указана → невозможно вывести, что происходит с лишними значениями. |
| Jaycadox/ysc-utils (`src/disassemble.rs`) | `Opcode::Leave { arg_count, return_address_index }` — только парсинг/имена полей | Не семантика исполнения. |
| njames93 / maybegreat48 декомпиляторы | LEAVE = `advpos(2)` / пропуск 2 байт; стек-модель на LEAVE не строится | Декомпиляторы не эмулируют VM. |
| unknowncheats, тред «Native registration table» (493135) | Содержит декомпилированный интерпретатор игры (`case 44u:` = NATIVE, `stack_pointer`, `scrProgram` — совпадает с нумерацией GTA V: 44=NATIVE, 45=ENTER, 46=LEAVE, 93=CALL) | **Не получен:** fetch страницы блокируется browser-check; контент найден только через сниппеты поиска (см. §5.2). |
| Vyzerythe/Leonida, PR #26 «RAGE Script Virtual Machine» | Сторонняя реализация интерпретатора (Call/Return/LEAVE) | **Недоступен:** репозиторий заблокирован по DMCA (HTTP 451, take-two, 2026-11-24). Даже при доступе — сторонняя реализация, не первоисточник. |

### 5.2 Что найдено сниппетами (пока не собрано в цельный источник)

- Из треда UC 493135 получен фрагмент реального кода интерпретатора (обработка `case 44u` NATIVE: `stack_pointer -= 2 * (param_count - has_return)` и т.п.) — доказывает, что тред содержит декомпиляцию интерпретатора с корректной нумерацией опкодов GTA V. **Кейсы 45 (ENTER) / 46 (LEAVE) / 93 (CALL) из этого треда ещё не извлечены.**

### 5.3 Итог по семантике на текущий момент

**Семантика LEAVE для GTA V RAGE Script VM НЕ ПОДТВЕРЖДЕНА.** Достоверно не установлено:

1. Откуда LEAVE берёт адрес возврата (из вершины стека по индексу `byte2`? из фиксированной позиции фрейма? из отдельного регистра?).
2. Что происходит с лишними значениями, оставшимися на стеке тела функции при LEAVE (отбрасываются при сбросе SP до базы фрейма? сдвигают позицию адреса возврата? молча игнорируются?).
3. Является ли `byte2` LEAVE индексом адреса возврата «сверху стека» (тогда для rcount=0 адрес возврата ждут на самой вершине и лишнее значение сломает возврат) или позицией от базы фрейма (тогда лишнее значение безопасно).

Следствие: **гипотеза «JZ→J безопасно, потому что LEAVE сбрасывает SP до фрейма» и контр-гипотеза «LEAVE прочитает лишнее значение как адрес возврата» — равнозначно неподтверждены. Ни одна не принимается за факт.**

### 5.4 Следующие шаги по семантике (в порядке приоритета)

1. Извлечь из треда UC 493135 кейсы `45/46/93` декомпилированного интерпретатора (повторный fetch / поиск сниппетами по `case 46u`, `return_address`, `instruction_pointer`).
2. Найти открытые реализации/эмуляторы YSC-VM (запросы: `ysc interpreter leave return_address_index`, `scrProgram LEAVE github`) и сверить их с описанием GTAMods Wiki.
3. Проверить первоисточник описания GTAMods Wiki (дата, автор, ссылки) — насколько оно авторитетно.
4. Если достоверного источника нет — зафиксировать в финальном отчёте: «семантика LEAVE не подтверждена; выбор варианта патча отложен».
